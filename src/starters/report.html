Builds are a third faster since the cache change

The build now reuses work from earlier runs. A typical build fell from about nine minutes to six, and fewer builds fail.

What changed

Each build step now saves its result under a fingerprint of its inputs. When the inputs have not changed, the next build takes the saved result instead of doing the work again.

The cache takes 40 GB of disk. It needs a size limit before it grows further.

Next steps

  1. Set a size limit on the cache and remove the oldest entries first.
  2. Check the slowest builds again in four weeks.

Sources: build logs from the last four weeks, about 1,200 builds. Times are medians.
